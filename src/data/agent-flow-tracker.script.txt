Next, I'll add Data Operation — Select after Get items.
For each expression, I'll open Insert expression (the fx editor), enter the expression, and choose Add. I'll keep the map's field names as plain text and use expressions for their values.
In From, I'll use the expression body('Get_items')?['value'].
This selects from the array of records returned by SharePoint, rather than the entire response.
I'll map five fields: ID, Title, Owner, DueDate, and Status.
ID uses item()['ID'], and Title uses item()['Title'].
In our prepared list, Owner uses item()['field_1'], DueDate uses item()['Dateandtime'], and Status uses item()['field_3'].
These are the internal names verified in an actual Get items test run. Learners should check the names in their own list rather than copy these custom field names automatically.
The ID gives the reviewer an unambiguous reference to an existing tracker record.
Now I'll add Respond to the agent after Select, then configure two Text outputs. Starting from the Workflows page does not add this action automatically. If you create the flow from an agent's Tools page and it already includes a response action, configure that existing action instead.
TrackerRecords uses string(body('Select')). This converts the structured array into JSON text for the agent.
LookupStatus uses if(greater(length(body('Select')),0),'Ready','NoRecords').
That expression checks the record count and returns Ready when records exist or NoRecords when the list is empty.
We don't need a separate Condition action here: Select returns an empty array for an empty input, and the status expression handles both cases.
This means the response is always defined after a successful retrieval, including the empty-list case.
A failed SharePoint retrieval must not be interpreted as an empty tracker or as permission to classify an action as new.
Under the response action's Settings, I'll confirm Asynchronous response is Off. This Standard agent needs the response during its request, within the 100-second action limit.
