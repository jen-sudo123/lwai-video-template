Microsoft 365 Copilot Agents are reusable mini-assistants you can configure for a specific workflow.

Instead of explaining the same task every time you start a new chat, you can give an agent a clear role, standing instructions, and selected knowledge sources.

Think of it as turning a strong prompt into a reusable assistant.

For this demo, I'll use the Microsoft 365 Copilot app to build Larry, an assistant that helps me write weekly leadership updates.

In the left sidebar, I open Agents, then choose New agent.

Here, I can describe the agent I want to build, or choose Skip to go directly to the configuration.

Since I already have my instructions prepared, I'll choose Skip.

I name the agent Larry, and add a short description: Helps me write weekly leadership updates.

Next is Instructions. This is where I define how Larry should work.

I'll paste in my /ˈkoʊdoʊ/ prompt. /ˈkoʊdoʊ/ stands for Character, Objective, Do's and Don'ts, and Output.

These instructions stay consistent. What changes each week is the input I provide, such as my notes, metrics, priorities, and blockers.

There's also a Suggest improvements option that can help refine the instructions.

Next is Skills. Skills give the agent additional instructions for repeatable tasks.

The menu offers two options: Create with chat, and Upload an existing skill package.

For Larry, my /ˈkoʊdoʊ/ instructions already cover the workflow, so I'll skip this section.

Next comes Knowledge. This is where I choose what information Larry can use.

First is Work content.

Here, I can configure sources such as cloud files, Outlook, Teams, and Copilot connectors, depending on my access and my organization's settings.

The goal is to select sources that are useful for the task.

For this demo, I want Larry to work only from the notes I provide, so I'll turn these sources off.

Second is Web search. This allows the agent to use information from the public web.

Larry doesn't need public information for this example, so I'll turn Web search off as well.

Third is Attachments. This lets me upload reference files directly from my device. I won't add any for this demo.

There's also a separate Knowledge settings area.

Here, I can see options for People data, creating documents, charts and code, creating images, and Discourage model knowledge.

Discourage model knowledge encourages the agent to prioritize selected sources over its general AI knowledge.

For Larry, I'll leave document creation available, and turn image creation off.

The configuration is now focused on the leadership update workflow.

Next is Suggested prompts. These are starter prompts that help people understand how to use the agent.

Each prompt has a title and a message.

For the title, I'll enter: Draft weekly update.

For the message: Draft this week's leadership update from my notes.

Now, someone opening Larry has a clear starting point.

Before creating Larry, I open Preview and test it with a realistic example.

I'll use fictional project notes containing progress, deadlines, a blocker, and a decision leadership needs to make.

The notes include completed onboarding, eighteen out of twenty tests passing, two open reporting defects, and a pending approval.

They also include a trade-off: assigning an engineer to the reporting fixes would help protect the pilot timeline, but delay a dashboard refresh by two days.

Once Larry responds, I check three things.

First, that it follows the five-section structure. Second, that it's concise and useful for a leadership audience. And third, that it accurately reflects the facts, owners, deadlines, and trade-offs I provided.

If the response needs work, I can refine the instructions and test again.

For example, I can specify that Larry should return one update, use only the five requested sections, and mark missing owners or dates as not specified.

Now I click Create.

Microsoft confirms that Larry was created successfully, and is currently private, available only to me.

Sharing options depend on my organization's settings. For this demo, I'll keep Larry private.

Then I choose Start chat.

Here's Larry, with the suggested prompt ready to use.

I can now provide this week's notes and get a leadership update, without pasting the standing instructions again.

I'll also check the response in normal chat before using it.

Once Larry is created, I can return to it in a few ways.

First, I can open Agents in the sidebar and select Larry.

Second, I can choose More agents, which opens the Agent Store, and find Larry under My agents.

Third, in a supported Copilot Chat experience, I can type at Larry, select it from the Agents and Skills suggestions, and bring it into the conversation.

The exact options may vary by Microsoft 365 experience, license, permissions, and administrator settings.

For more advanced automation, actions, or integrations, you can explore Copilot Studio.

For a repeatable task like a weekly leadership update, Agent Builder gives you a practical starting point.

You define how the assistant should work once, test it, and then reuse it with fresh inputs each week.
