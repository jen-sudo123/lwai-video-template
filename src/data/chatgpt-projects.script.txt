If you've ever thought, "Why do I have to explain everything again?", you're not alone. ChatGPT can remember relevant information from previous conversations. But when you're working on an ongoing project, your chats, documents, and instructions can still end up scattered. That's where ChatGPT Projects comes in. A Project brings related conversations, reference materials, and instructions together in one workspace. For recurring work, that means less time setting up, and more time moving the work forward. Let's build an example: Larry, an assistant for weekly leadership updates.

[pause] From the Home sidebar, I'll find Projects and click the plus button beside it. I'll name this project Larry, Leadership Updates. I can also choose an icon and a color, so it's easy to recognize. I'll use a blue bar-chart icon.

[pause] Next, I'll open the memory menu. This account offers two options. With Default memory, the project can use memory from outside chats, and the other way around. With Project-only memory, conversations in the project stay in the project. For Larry, I'll choose Project-only memory, so the work stays focused on leadership updates. There is a trade-off. This setting currently turns off Work mode and access to my file Space in this project. I can still upload reference files directly to its Sources. Now I'll click Create project.

[pause] With Larry created, I'll open the three-dot menu beside the project name and select Project settings. The Instructions field is where I define how Larry should work, across every conversation in the project. I'll use my Koh-doh framework. Character: act as Larry, my Chief of Staff. Objective: turn rough weekly notes into decision-ready leadership updates. Do's and Don'ts: highlight progress, risks, decisions, and next steps. Don't invent missing information, and clearly flag unknowns. Output: a concise update with clear headings, no more than two hundred words. I'll paste those instructions and click Save. Now Larry has reusable guidance, so each week, I only need to bring fresh notes. Project settings also has a Memory selector, so I can review the memory setting later.

[pause] Next, I'll open the Sources tab and click Add sources. On this account, I can upload a file, paste text, or add a supported Google Drive or Slack source. Available connections can vary by account and workspace. For this demo, I'll upload a short, fictional strategy document. It gives Larry two pieces of context. The customer-health dashboard should launch by the 30th of November, 2026. And the target is 95 percent data completeness across pilot accounts. Once the upload finishes, the file appears in the project's Sources list, ready for Larry to use alongside my weekly notes.

[pause] Now I'll start a chat inside the project and ask Larry to turn these notes into this week's leadership update, highlighting key developments, decisions needed, and next steps. Then I'll paste my meeting notes. The dashboard pilot is live with 12 accounts. Data completeness improved from 82 to 91 percent. Two data connectors are delayed, and Maya will provide a recovery plan by Friday. Leadership needs to decide whether connector fixes take priority over a new export feature. There's a data-quality review on Thursday, and a launch-readiness check on Friday. And the budget impact hasn't been assessed. Notice that I haven't repeated the target or the launch deadline. Those are in the reference file. Before I send it, I can also adjust the reasoning level from the message box. On this account, the control shows High, and opens a Thinking effort slider.

[pause] I'll send the request and review Larry's response. The update brings the notes together with the 95 percent target and the November deadline. It also flags the unknown budget impact, and the missing action owners. That's the benefit of combining project instructions, reference sources, and fresh input. I still review the result before using it, especially its assumptions, dates, and recommendations.

[pause] If a response is useful, I can click Add to project sources, right beneath it. Back in Sources, I can now see both the strategy file and the saved leadership update. That keeps a good output available as reference for future work. Next week, I can come back to Larry, start another chat, and bring fresh notes.

[pause] There are two more controls worth knowing. First, moving an existing chat into a project. In the Home sidebar, I open the chat's three-dot menu, select Move to project, and choose a destination. Use the sidebar menu for this. The menu beside the chat title may show different options. Second, sharing a project. From the project page, I click Share to review access and invite collaborators. This workspace offers two choices: only those invited, or anyone at Lead with AI with the link. Your options may differ. Before sharing, check the access level and the project's contents, because collaborators can see shared project material. The dialog also explains that shared projects turn off personal memory and Google Drive sync.

[pause] Larry now has a dedicated workspace, with instructions, reference material, and a reusable leadership-update workflow. That's the value of Projects: keeping ongoing work organized as it develops. Start with one recurring task. Give it clear guidance, add the reference material it needs, and build a workspace you can return to every week.
